# 羽球助手

这是一个用于组织羽毛球局的单页应用。前端入口是 `index.html`，数据保存在 Cloudflare D1，并提供 GitHub Pages 只读备用入口。

接龙助手会根据当前名单、星期、短期及长期规则、体力、成员关系和随行人员历史，估算今天与明天达到 6 人的概率。摇人列表只推荐近30个已完成自然日内有本人订场接龙记录的成员，固定按到场概率从高到低排序，不再提供到场概率/成局概率排序切换按钮；成员行直接显示「到场概率 N%」，以当天能组织球局为前提，按实际成局日的个人出勤比例、近期真实接龙和当天条件估算；百分比为普通文本，不带下划线或点击交互，顶部说明概括影响因素。成员行仅显示到场概率，不再显示「成局概率 +N%」，也不再提供显示/隐藏按钮；顶部整体成局概率汇总、筛选及手动置底保持不变。它不是邀约答应率，也不会随剩余报名时间机械压低。Cloudflare 管理版会在后台保存去重后的接龙状态；试算模式和 GitHub 只读版不会进入学习数据。模型按 30 天半衰期自动吸收成员频率、留存、体力、带人、大局偏好和方向性关系，新成员使用群体先验冷启动，全程不调用大模型。模型口径见 `docs/group-formation-probability.md`。

## 数据库成员管理

- 默认显示「名称、性别、中羽等级、备注、所属、球友群序号、Hytronik群序号」；右上角的列图标可切换照片、等级介绍与历史统计等字段。
- 点击右上角「+」或在数据库页面按 `Alt+N`，打开新建成员弹窗，一次填写名称、性别、中羽等级、备注和所属。名称必填，其他字段沿用原有默认值；群序号由后端按所属自动分配。
- 表格不再保留输入姓名即自动保存的空白行。提交前不会新建或重排成员；保存失败时保留填写内容，保存中禁止重复提交。成功后定位新成员；若当前筛选隐藏了该成员，会提示而不清空筛选。
- GitHub 备用版和离线数据继续只读，不允许新建成员。摇人窗口内的 `Alt+N` 仍用于新建短期规则。

使用 `npm run test:database-ui` 验证默认列、新建弹窗、校验、失败重试、重复提交防护、筛选、只读状态及快捷键。

## 小程序报名名单整理

完整的小程序活动文本仍可生成原有的删减分享版。“试算”旁的“只保留报名名单”图标按钮会移除标题、活动说明、场地和报名链接，只留下原顺序的编号报名行；中间卡片随即恢复可排序的接龙列表。

带方括号等级的报名行以 🌸 标记确定性别：有标记为女，无标记为男。方括号中的等级不参与计算；已匹配成员使用数据库等级，陌生人或随行人员显示等级下拉框，由管理员手动设置。手动编辑只影响本次接龙，不改写左侧原文或成员数据库。编号随行人员和重复报名保留独立的性别、水平及归属，试算开关状态不受整理操作影响。GitHub 只读版同样支持本地整理与等级选择。

使用 `npm run test:special-roster` 验证 33 人示例、原文保留、等级来源、性别统计、排序、随行人员和普通接龙回归。

## 自定义等级分组

在“接龙助手 → 人数统计 → 高级 → 等级分组”修改名称、添加或删除分组，并选择起止等级。默认仍为新手（0.5～2级）、中手（2.5～3.5级）、高手（4～5级）、比赛级高手（6～9级）。支持 1～14 个分组，名称限 20 字且不能重复，范围包含两端且不能重叠；没有覆盖的已知等级单列为“未分组”，等级不详仍独立统计，人数不会遗漏。

点击“保存分组”后，接龙的分组显示、人数统计、随行人员等级选项和摇人等级筛选同步更新；精确等级模式仍显示实际等级。随行人员选择分组时，以选项括号内标明的等级计算；旧名单的默认分组文字继续兼容。编辑器每行以“名称、起始等级 ~ 结束等级、×”紧凑显示，保留“新增分组”和“保存分组”两个操作。编辑和删除先修改草稿，点击保存后才生效。

Cloudflare 管理版保存到 D1 的 app_settings.level_groups，重新打开后跨设备读取；GitHub 备用版或离线状态只保存到当前浏览器，页面会明确提示保存范围。分组配置不改写成员等级、历史逐人快照或账单；数据库中已有设置也会随部署快照发布。无需新增数据表或迁移。

使用 npm run test:level-groups 验证范围校验、人数守恒、旧标签重算、下拉框和云端接口。

## 场地费

默认每场 3 小时 70 元；提前结束按 1 小时 24 元、2 小时 47 元计费。“费用计算 → 高级”的场地数量通过上下按钮或方向键按 1 小时增减，显示为 0.333、0.666、1、1.333、1.666、2……；1.333 场为 70 + 24 = 94 元，1.666 场为 70 + 47 = 117 元。金额按实际时长档位计算，不直接乘以截断的小数。多个提前结束的场地应分行填写（两个 1 小时场地为 24 + 24 = 48 元）。

前端、群收款、订场保存及费用明细共用同一计费规则；手动修改的非 70 元单价仍按单价乘数量计算。历史半场记录继续兼容，已保存账单不自动重算。

## 群收款规则

默认女生每人比男生少 3.50 元，其余费用由男生分摊（只有一种性别时仍均摊）。在“费用计算 → 高级 → 群收款规则”可选择三种互斥方式：

- **男女平 A**：总费用除以付款人数，向上取整到分。
- **女生比男生少 A**：填写每位女生的减免金额 D。总费用为 T、付款人数为 N、女性人数为 F 时，男性单价为 `(T + D × F) / N` 向上取整到分，女性单价为男性单价减 D。女性最低付 0 元，剩余费用由男性均摊。
- **女生金额封顶**：填写每位女生的上限 C。未超过上限时仍均摊；超过时女性单价为 C，剩余费用由男性均摊并向上取整到分。

金额允许 0，最多两位小数；空值、负数、非数字或超过两位小数时禁止生成群收款。只有一种性别时仍按人数均摊；性别不详按男性单价计算。随行人员按自己的性别计算，再按归属人汇总。所有收款金额、分组合计、复制文本、记录金额和费用预估统一使用所选规则并显示两位小数。

规则仅用于当前页面的本次计算，切回基础费用视图不会重置；刷新页面或从日历新建/编辑一场时恢复女生比男生少 3.50 元。已保存的历史账单不自动重算，主动编辑并保存时按当前所选规则重新计算。

例如总费用 115 元、3 男 1 女：默认男 29.63 元、女 26.13 元；选择男女平 A 时每人 28.75 元；设置女生 25 元封顶时男 30.00 元、女 25.00 元。向上取整可能产生每人不足 0.01 元的总差额。使用 `npm run test:payment` 验证默认、减免、封顶、边界、归属汇总和显示。

## 同一天的多场球局

选中日期后，无论当天是否已有记录，都可点击记录列表左下方的“新增记录”添加独立记录，同一天不限一场。每场分别保存成员、费用、球馆和训练选项；新增不会覆盖当天已有球局。日期格右上角显示多场标记（如“2局”），场地数量按天合计，不同球馆显示“多球馆”。下方按第1场、第2场逐条展示，可分别切换球馆、编辑或删除。月份/所选日期统计同时显示球局数和场地数，记账仍按所有记录合计；只读备用版仅展示，不提供修改入口。

## 订场日历汇总

汇总统计行将标准小时场地按 3 小时折算：1 小时为 0.333 场、2 小时为 0.666 场，累计真实时长后显示，例如 `70元×8.666个`。这仅是数量展示，实际费用仍按每次订场的 24 / 47 / 70 元档位计算，不将折算小数乘以 70；其他历史价格仍单独显示。

男性、女性平均费用分别按已保存的个人费用合计除以该性别的人次计算，随行人员使用自己的性别和金额，不按归属人的性别计算。无该性别人次时显示“暂无数据”；性别不详或旧记录合并了多人、无法拆分金额的记录单独注明，不猜测其性别及金额，但费用仍计入总额。使用 `npm run test:calendar-summary` 验证。

## 订场日历记账

日历顶部月份场次统计行右侧的“显示记账 / 隐藏记账”按钮可同时控制日期格和下方汇总栏的金额显示。日期格右下角按天合计，空白日期不显示，有记录的零金额与负金额正常显示；汇总栏按当前月份或所选日期合计。每次重新进入订场日历时默认隐藏。

计算复用群收款的记账口径：按归属人汇总已保存的参与者金额，排除 choi 的应收金额，再扣除场地费，不重新计算历史分摊价格。使用 `npm run test:calendar-ledger` 验证计算与显示。

## 随行人员口径

接龙里的 `+N`、`＋N`、`➕N`、`代N` 和 `加N` 表示编号为 N 的一位随行人员，并不表示一次增加 N 人。新记录会为每位实际参与者保留独立的性别、水平快照及归属人：接龙助手逐人展示，训练预估按包含随行人员在内的总人数计算；群收款、订场确认、订场日历、成员统计和导出则按归属人汇总金额和带人数。归属人缺席时不增加其打球次数，也不参与该场同场/拍档统计。

旧记录继续使用 `slots` 和 `plusCount` 保留总人数、金额和带人数。旧随行人员从未保存过的性别与水平统一视为“不详”，不会从归属人推断或补造。

## 退群排查

管理版可以上传群成员列表截图，OCR 只负责提取当前序号和可见名称；管理员再用数据库成员设置人工锚点，系统根据新旧序号差值给出可能退群范围。数据库中未录入的序号空位也会保留为候选，分析结果不会自动删除任何成员；单个或多个候选都必须人工确认，并按旧序号从大到小处理。

最终确认前会重新获取云端成员序号并比较候选签名；专用确认接口还会校验当前群的完整序列，资料已变化时返回冲突并停止。双群成员只退出当前群，单群成员才删除档案，未录入成员只调整当前群后方序号，不会连带保存其他群收款设置。

截图仅在本次请求中发送给 Cloudflare AI 做识别，不写入 D1、R2、数据快照或浏览器持久存储。接口只接受 PNG、JPEG 和 WebP 原图，单张不超过 6 MiB；识别人数与管理员填写人数不一致时拒绝继续分析。

## 摇人概率与成员标签

- 个人到场概率与整场成局预测分开：只把实际成局日作为出勤机会，按30天半衰期加权；成员总体出勤向有真实参与记录的成员平均值平滑，同星期出勤再向个人总体平滑（各6个伪样本）。未参与过的通讯录成员不稀释此先验，入群前/无球局/当天及未来记录不当缺席，同日多场只计一天。继续应用真实接龙画像、同场关系、体力、人数偏好和当天规则。
- 不把自然报名模型的全局截距、剩余时间因子或模拟命中次数直接用于列表百分比；大局规模参考实际成局日的历史规模和当前已报名人数，而非剩余时间模拟。没有统一放大倍数或百分比下限，当天明确不打仍为0%。整场成局概率继续随报名时间变化，原自然到场估算保留在诊断字段 `naturalAttendanceProbability`。

- 顶部显示“日期   当前成局概率 N% · 推荐 N 人”；成员行显示“到场概率 N%”和“成局提升 +N个百分点”。后者是成员**确定到场与不到场**两种情形的概率差，单位为百分点，不是直接加到当前概率上；悬浮提示中保留了说明。
- Cloudflare Cron 每天 **北京时间 00:05** 重算成员统计并检查节假日日历；**12:05** 自动结算、重建组局学习模型并再次更新统计。真实接龙样本用于学习，试算名单继续排除。
- 标签统一读取当前成员统计，并在统计、已完成订场、接龙人数或目标日期变化时重新生成；普通推荐和回退推荐口径一致，不复用旧预测中的统计标签。当前符合条件的标签逐项显示，不再被两个标签的截断隐藏。
- “近期常打”对应15天出勤榜，另要求15天内至少2个不同出勤日期，避免单次/同日多场的小样本误判；旧的历史参与、带随行人员和“近30天参与N天”标签删除。原有同场关系、水平、规则、体力等标签继续保留。
- “周X可能无法打球”只在当天为周X且对应统计名单包含本人时显示，节假日和调休日不显示此推断。
- “每周可能最多打1局/2局”只在对应周上限名单中、且本周已完成出勤达到上限时显示；观察期内任意一周出现2次就归两局组，出现3次及以上就退出这两组，修改/删除历史记录后即时重算。周窗口仍是周一至周日，只统计近30天内已完成记录。
- “可能不喜欢人少的局”要求属于“只打10人以上”名单，且当前接龙总人数不超过10人；11人及以上隐藏，人数下降后恢复。总人数包含实际列出的随行人员。
- 成员统计右上角刷新按钮：Cloudflare 管理版执行结算、重新训练组局模型、重算统计/日历，然后拉取最新数据并更新标签；刷新中禁止重复提交，失败保留页面数据并可重试。GitHub/离线只读版只尝试拉取最新云端模型并重算，不调用训练写接口，按钮说明和完成提示明确区分。


### 自动成员统计（2026-10-23）

- 摇人界面仅保留一个“成员统计”下拉区，每次打开摇人时默认展开，用户仍可手动收起；包含15天出勤排名、两/三天连打、人数偏好、七个星期偏好、一/两局周上限和最佳拍档，共14项。最佳拍档支持手工创建、排序和持续排除（仅Cloudflare管理版可写），其他统计名单只读；“新建规则”可继续创建、查看和删除日期或星期安排。
- 所有窗口以**北京时间昨日**为最后一天，含首尾，分别回看15、30、60个已完成自然日。当天及未来安排不提前进入历史。近60天没有本人接龙记录的成员不参加任何统计；随行、只代报 +N、通讯录中从未接龙的人不计本人出勤。
- 排名按15天接龙**场次**降序，同次数同名次；同一场内按成员去重，同日不同场仍分别计次，同一场 ID 的重复记录去重。界面不显示序号，只显示前10人，截止第10人的同次数成员全部保留；15天0次不上榜，不足10人不补齐。
- 连打按60天不同日期连续性计算，最大连续≥3天归三天组，恰好2天归两天组，不重复。
- “只打10人以上”“不打周X”“每周最多打X局”均要求近30天本人至少2次接龙；同日不同场分别计次，重复场次和代报不增加本人的次数。此门槛不影响15天排名、连打组和最佳拍档。
- 人数含随行人员，逐场判断；仅所有场次都**至少11人**的成员属于“只打10人以上”。只要有一场10人或更少即排除。
- 星期偏好看30天：列表只纳入近30天本人接龙至少2次的成员；排除国务院公布的整个放假日期和调休上班日期，剩余普通日期中从未在某星期接龙即归类。未知年份日历不擅自按普通工作周推断。当前内置2025、2026官方安排，定时从 `NateScarlet/holiday-cn` 的国务院公告数据镜像检查更新，验证年份、日期、公告来源；请求失败保留已验证日历。
- 周上限按周一至周日分组，仅统计30天窗口内的场次（边界周不扩展窗口）。观察到的周最大值恰好1或2分别归对应组；两组互斥，30天0场不虚构上限。
- 展示、API与概率模型共用 `member-statistics.js`。统计提供15天近期频次、连打能力、大局偏好、普通星期缺席倾向、已用周局数信号，同时参与个人到场与成局模拟；自动推断只作软证据，明确新建规则仍具有不打约束。历史手工名单写接口返回410，不删除旧数据。
- 最佳拍档看近90天的已完成订场，双方近30天有出勤，按同场/分别出勤的双向关联而非总同场次数排序；近期30天半衰期、同星期和30天时期校正、双方入群后的共同观察期、小样本门槛均参与判断。同日多场合计最多一天权重，且必须真实同场。默认展示前10组，其余可展开；每组可查看双方原始条件出勤比例。首次仅展示双人组合，不自动串联多人朋友圈，不显示“好友概率”，也不接入到场或成局概率模型。详细口径见 `docs/best-partners.md`。日历详情和旧推荐回退标签改称“同场最多”，保留原来的同场次数算法。
- 统计名单门槛与推荐活跃筛选仅影响页面展示：推荐需近30天本人至少1次接龙，正常预测和回退路径均执行；筛选、排序、重新打开和跨日刷新不绕过门槛。统计名单要求2次并不等于推荐要求2次。模型大局偏好改从未过滤的成员特征读取，保持原有概率公式、特征和剩余成员排序，不因缩短展示名单改变预测。
- `GET /api/member-statistics` 和 bootstrap 使用实时接龙重算，浏览器跨日、重新打开摇人窗口、修改已完成接龙时刷新，不必等待下一次定时任务。`POST /api/member-statistics/refresh` 用于管理员重新训练并刷新（沿用来源校验和限流），`POST /api/member-statistics/rebuild` 保留原来的仅刷新持久化快照及日历功能；快照存于 `member_statistics_cache`。

## 摇人与最佳拍档（2026-10-27）

最佳拍档全部展示，悬停/键盘聚焦显示管理按钮，手机常显。人工修改保存在D1并同步GitHub只读端，删除不会被自动统计恢复，排序不影响概率。日历使用相同名单，无拍档才回退到所选范围的同场最多。新朋友标签与概率均只认直接拍档关系。v4概率模型共享标签资格，去除旧共场重复加成，按实际证据处理周习惯、连打和朋友共同参与；UI跳过不显示的反事实计算。详见 `docs/best-partners.md` 和 `docs/group-formation-probability.md`。

## 文件说明

- `index.html`: 主界面和所有前端交互。
- `src/worker.js`: Worker API，负责连接 D1。
- `data/bootstrap-snapshot.json`: 随版本发布的 D1 数据快照。
- `scripts/generate-snapshot.js`: 从远程 D1 生成最新快照。
- `scripts/train-estimator.js`: 使用最新 D1 订场记录训练场地容量和各球型号的独立权重。
- `data/booking-estimator.json`: 当前部署使用的预估模型参数。
- `docs/booking-estimation.md`: 预估规则、固定排除记录和后续更新说明。
- `migrations/0001_initial.sql`: D1 表结构。
- `migrations/0012_participant_owners.sql`: 随行人员归属字段及可确定归属的历史逐人记录回填。
- `scripts/verify-chain.js`: 使用需求里的示例验证接龙和群收款规则。
- `scripts/verify-participant-ownership.js`: 随行人员归属、统计投影及字段贯穿的可执行契约测试。
- `scripts/verify-member-exit-analysis.js`: 截图退群排查的锚点算法、候选范围和 OCR 接口契约测试。
- `scripts/verify-estimator.js`: 验证 v5 逐型号分层公式、性别/等级/成员差异、异常阈值、模型快照同步和历史回放。
- `member-statistics.js`: 浏览器、Worker与发布快照共用的14项成员统计。
- `scripts/verify-member-statistics.js`: 统计窗口、归属、互斥、节假日、周边界、预测集成及SQLite缓存测试。
- `migrations/0024_member_statistics_cache.sql`: 每日成员统计快照及已验证日历。
- `group-probability.js`: 可在浏览器和 Node 中运行的组局概率与摇人排序核心。
- `src/group-learning-core.js`: 从订场和真实接龙快照生成时间衰减的自适应成员画像。
- `migrations/0017_group_attempt_tracking.sql`: 接龙尝试、状态快照和短期规则历史。
- `scripts/verify-group-probability.js`: 验证星期基线、截止时间、体力、大局门槛、随行人员、明日预测和反事实排序。
- `scripts/verify-group-learning.js`: 验证新成员冷启动、频率变化、留存、体力、大局偏好、带人和方向性关系学习。
- `scripts/verify-group-attempts.js`: 验证追踪校验、去重、试算隔离、自动结算和订场对账。
