# 订场预估模型

接龙助手会根据参与者的中羽等级、性别和已有成员历史，分别预估场地数量与亚3等价用球量。等级和男性影响只允许提高需求；个人修正值按历史参加场次收缩，避免少量记录被过度解读。

## 固定规则

- 场地预测不使用球馆、场地价格或场地质量。
- 11、11.3、11.5 元对应亚3（亚狮龙3号）。
- 13.5 元对应 AS05（尤尼克斯 AS05）。一颗 AS05 暂按 1.2 颗亚3的耐打量换算。
- 未登记的球价必须提示登记球型号，不自动套用已知球型。
- 等级、性别未知时，依次回退至已知单项特征和整体人群均值。
- `+N` 是独立临时球友，不关联数据库成员；记录时保存当场性别和等级快照。
- 场地和球数取整时向上取整，避免少订场或少带球。

## 排除记录

- 2026-08-04：球友请客，实际用球数量不完整。
- 2026-08-10：低水平且场地拥挤，实际订场数量不代表常规需求。

这两场永远不参与训练，除非明确修改本文件和 `scripts/train-estimator.js` 中的排除清单。

## 数据记录

订场记录应保存每位参与者当时的性别、等级；数据库成员之后更改资料时，历史快照不回写。临时球友应以单独的一行保存，`player_id` 留空。球型号保存在每个球价行的 `type` 字段中；旧记录会按价格自动识别。

## 更新模型

执行 `npm run estimator` 会从 Cloudflare D1 获取最新成员和订场记录，重新训练并写入 `data/booking-estimator.json`。随后执行 `npm run snapshot` 和 `npm run build`，将模型加入 Cloudflare 与 GitHub 的只读快照。

以后可直接对 AI 说：

> 请看预估模型文档和最新的订场数据，更新一下预估公式。

AI 应先检查本文件、保留固定排除记录和球型号规则，再训练、验证、更新模型文件；除非明确要求，不应直接部署。
