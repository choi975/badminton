# 场地安排

## 使用

接龙助手整理后名单右上角的布局图标打开“场地安排”。窗口默认是完整画布，右上角依次为复制、偏好与小团体、关闭三个图标按钮；偏好图标再次点击返回画布。“摇人”顶部也保留“小团体与偏好”入口。

- 默认场地数为 `max(1, ceil(接龙人数 / 7))`，只是起点；7人显示1片、20人3片、23人4片。可手动增减，不要求每片至少5人。
- 场地编号是独立标签，可填2、3、7、8等非连续编号。拖动场地左上角的把手调整相对位置，方向键也可移动；横排、竖排和自动排列是快捷整理工具。
- 框内人名为固定人员，框外为流动人员。每个人只出现一次，流动人员不会重复计入全员人数。
- 相同去向的分组框与可去场地通过边缘到边缘的直线相连，没有直角折线或多余人数标题。选中个人只展开他的直线去向，选中场地高亮可串入人员。小团体单独高亮，不与串场线混画。
- 拖人进场地框改为本次固定安排；拖到框外改为流动，可独立摆放。拖回流动分组框时会清除独立坐标，自动排列回框内；拖入另一分组框会采用该框的可去场地。悬停的放置目标会高亮，空分组框仍可接收人名。
- 不再显示固定右侧建议区、活动人数摘要和两个页签。选中人名后可用工具栏编辑图标、双击或F2打开临时个人编辑面板，设置场地、串场范围、锁定和偏好；独立人名也可用“放回流动分组”按钮收回。Escape先收起个人编辑，再关闭窗口。
- 手动安排自动锁定，重新建议保留锁定人员、场地编号和布局。取消锁定即可重新参与推荐。
- “复制安排”生成可发给球友的文字名单。

## 建议规则

按照中羽半级等级排序并进行相近等级的连续分配。场地基础人数只是次要的分组参考，不作为硬性容量要求。

默认0.5～1.5级固定，2～2.5级流动；3级及以上在尚未确认偏好时暂按固定处理，不擅自认定其只打高手局或愿意带人。明确的个人偏好覆盖默认规则。等级不详不猜测，可只补充本次等级，成员数据库不变。

“只打高手局”的3级及以上固定人员达到6人，且可以将其他人员分流到另外的场地时，优先形成高手专场，自动建议不让普通流动人员串入。不足6人、其余人员无法凑齐四人，或只有一片必须共用的场地时允许补位。手动串入专场保留选择，同时提醒检查对局偏好。

高手的带人偏好可以是未设置、愿意带朋友、指定名单或广泛愿意陪低等级球友打。指定／朋友型带人的高等级流动人员优先连接相近等级及对应朋友所在的场地。关系有方向：被带者不会自动获得高手的串场权限；随行人员不会继承报名人的偏好。

混搭没有强制逐局排赛。不把每次串场限定为两边一高一低，也不把等级简单相加当成必然的实力匹配。最终具体对阵、双方意愿和现场四人补位由组织者确认。

## 小团体

支持人工维护2～8人小团体，一个人可属于多个团体。原有效“最佳拍档”作为两人关系展示，可扩展为一个人工确认的小团体；不替换原拍档数据，不改变已有摇人／到场概率模型。

自动候选仅从相互存在的最佳拍档关系中提出，需组织者确认；A—B、B—C不会自动合成A—B—C。没有调用外部大模型，不能仅凭同赴活动记录判定真实小团体或带人意愿。手动关系不会被候选覆盖。

## 保存与兼容

Cloudflare和GitHub Pages均可编辑本功能的安排、个人偏好和小团体；这是排场配置，不开放GitHub版原有成员数据库、账务或拍档模型的写权限。

- 长期偏好／小团体使用全局文档；本次临时偏好、人员位置、连线范围、场地编号和布局按接龙活动日期独立保存。
- 草稿先备份浏览器，再后台同步D1。失败可重试；初始云端读取失败不会直接用本机草稿覆盖未知版本。
- 比较并交换版本防止跨设备覆盖，支持采用云端或明确确认保留本机。相同操作编号的丢失响应重试不会重复增加版本。
- 首次部署应用迁移 `0031_court_arrangements.sql`，仅新增 `court_arrangement_documents`，不改历史订场、成员、费用或最佳拍档。
- 活动日期尚未整理确认时，排场入口提示先确认日期；仍可编辑长期偏好和小团体，但禁用本次排场与复制，不保存活动文档，避免把历史／未来名单误存到当前日期。

## 验证与文件

`npm run test:court-arrangements` 验证69条本地历史订场、默认人数／等级、3人固定场、高手专场、方向性带人、非传递关系、锁定和布局、身份隔离、输入校验、D1保存、幂等重试、冲突和日期隔离。

`node scripts/preview-court-arrangements.js` 在 `http://127.0.0.1:8787` 提供完整应用预览及隔离的内存SQLite，仅在测试环境将线上API地址替换为本机地址，不产生线上写入。用于Windows本机workerd不可启动时的界面验证，不能用于生产部署。

生产文件：`court-arrangement-core.js`（纯规则／校验）、`court-arrangement.js`（画布／交互／客户端同步）、`court-arrangement.css`（继承应用tokens的独立样式）、`src/court-arrangements.js`（D1接口）。`scripts/sync-public.js`统一生成Cloudflare文本资源和GitHub Pages静态文件。

## 当前范围

只考虑接龙全员到场后的场地安排，不处理到达时刻、分时订场、中途增减场地、自动轮换时间表或逐局四人对阵。连线表示可去范围，不是实时人数监控或同时占用承诺。

真实浏览器回归：先启动隔离预览服务并打开 `http://127.0.0.1:8787`，再运行 `npx --package @playwright/cli playwright-cli --session court-arrangement run-code --filename scripts/verify-court-arrangements-browser.js`。测试脚本检查隔离标记，只向本机内存数据库写入；覆盖实际指针拖动、编号、6人高手专场、小团体、复制、焦点、丢失响应、冲突、初始读取失败与跨日期草稿恢复。
