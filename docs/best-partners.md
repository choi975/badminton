# 最佳拍档与摇人成员统计（2026-10-23）

## 范围与非目标

`member-statistics.js` 是浏览器、Cloudflare Worker、GitHub 发布快照共同使用的纯计算模块。成员统计 v3 共14项。此次调整只影响展示名单及推荐资格：保留组局和个人到场概率公式、原有成员特征及合格成员之间的排序。模型大局偏好直接读取未过滤成员特征，不受展示门槛影响。

- 15天排名继续按真实订场场次计数，显示姓名和次数、不显示序号。取排序后第10个人的次数作为截止线，同次数全部保留；不取“前10种次数”。0次不展示，不足10人不补齐。
- 成员统计在每次打开摇人时默认展开，手动收起后不会被筛选或自动刷新强行展开。
- “只打10人以上”、七项“不打周X”和两项“每周最多打X局”要求本人近30天至少出勤2次；不影响其他统计。同日不同场计2次，重复ID及只有随行人员的记录不算本人出勤。
- 推荐成员要求近30天至少1次本人记录，不是2次；预测正常和回退路径都过滤，当前已接龙成员和已有规则继续按原逻辑排除。
- 七项“不打周X”的节假日和调休继续不参与星期判断。模型使用的 `members[].noPlayWeekdays` 特征不在此次顺带改写。
- 新增最佳拍档，只呈现证据充分的无向双人组合，按分数排序，组合不重复。前10组直接显示，剩余组合可以展开，每组也可以展开查看双向历史条件比例。
- 日历详情的旧列及推荐回退标签改名为“同场最多”，仍使用该功能原来的场次统计和时间范围；新算法不替换概率模型已有的关系项。
- 第一版不把 A—B、B—C 自动拼成 ABC 朋友圈，不使用姓名白名单、人工加分、朋友概率或外部大模型。

## 数据口径

1. 截止北京时间昨天，回看90个已完成自然日，含首尾。双方都须在最近30天有本人记录。
2. 数据来自已保存的实际订场，不把未成局接龙、试算快照、未来安排作为出勤。这里“接龙记录”沿用原成员统计的完成订场口径，不声称覆盖所有历史报名过程。
3. 只有本人出场才计入。随行人员、本人缺席的 +N/代报、重复成员行不代替本人；重复 session ID 去重。
4. 比较每对成员时，只取双方加入后的共同观察期。成员起点取资料登记日期和首次真实出勤中较早者；未知登记日期时以首次真实出勤为准，不虚构入群前缺席。
5. 没有订场的日期不产生“共同缺席”证据；有球局但两人均未参加是有效对照。即使该场只有其他人或随行人员参加，也保留该机会。
6. 同场要求同一份订场名单。两人同一天参加不同场不算共同出勤。每个有球局的日期合计最多一天统计权重，均分给当日各场。最低样本数按不同日期计，原始解释比例仍按场次计。

## 计算

每场形成二乘二表：共同出勤 `n11`，仅A `n10`，仅B `n01`，均未参加 `n00`。权重为：

```text
w = 0.5 ^ (距离截止日天数 / 30) / 当天有效订场数
```

先计算双方总体加权出勤率，再向各自总体率加入4个伪样本：

```text
A来 | B来 = (加权n11 + 4 × A总体率) / (加权B出勤 + 4)
A来 | B不来 = (加权n10 + 4 × A总体率) / (加权B缺席 + 4)
A方向差值 = 前者 - 后者
B方向对称计算
```

为了避免只反映固定时间或同时活跃的时期，另作两种保守校正：

- 按星期分层。已验证的放假、调休日期放在独立特殊日期层，不视作普通星期。
- 按距截止日0–29、30–59、60–89天三个时期分层。

每种分层都累加层内协方差与方差：

```text
C = Σ层 (n11 - A出勤 × B出勤 / N)
VA = Σ层 A出勤 × (N - A出勤) / N
VB = Σ层 B出勤 × (N - B出勤) / N
A方向差值 = C / VB
B方向差值 = C / VA
```

层内没有来/不来对照时，对应差值记0，不以总体高重合率替代。最终各方向取“平滑总体差值、星期校正差值、时期校正差值”三者中的最小值。这是保守的两种分别分层校正，不是声称完全排除了所有混杂因素的因果模型。

证据可靠度与排序分数：

```text
可靠度 = 共同出勤天数 / (共同出勤天数 + 5)
       × min(1, 双方较少的缺席天数 / 5)
分数 = max(0, 双向校正差值中的较小值) × 可靠度
```

门槛统一配置在 `PARTNER_POLICY`：共同观察期双方各至少5个出勤日期、共同至少3天、各至少3个未出勤对照日期、共同记录跨度至少7天；双向校正差值都至少0.15，最终分数至少0.12。分数仅是排序指标，**不是朋友概率或邀约成功率**。人数多、出勤多本身不保证入选；证据不足留空。

评分和输出顺序确定；保持稳定加总顺序，API、浏览器和快照共用同一算法。资格判断使用未舍入的值，输出保留六位小数。
