# 接龙名单与七天球局计划

## 交互

- 移除接龙助手的一键粘贴、试算开关；仍可正常粘贴文字和提取小程序接龙。
- 悬停或聚焦成局概率可查看今天与未来六天，点击打开“球局计划”。
- 窗口固定七行，每行十格。单击格子后点成员卡片填入；双击格子或使用“自定义”按钮手动输入，Enter 保存、Escape 取消；Backspace 或“清空格子”删除（Delete 不清空格子）。
- 没有选中格子时，先点成员卡片，再连续点日期，可向多个日期追加该成员；点击其他位置退出成员选择。满十格时提示，不覆盖已有成员。
- 同日重复成员代表随行朋友：首个是本人，其余只计人数和归属，不重复计算本人或拍档关系。陌生名字不自动创建数据库档案。
- 下方卡片显示近15个完整北京时间日期内有实际本人出勤的所有成员，按次数降序，不限制前十名。卡片默认只显示姓名；鼠标悬停或键盘聚焦时，才显示近15天实际出勤次数及相关风险、拍档提示。计划与朋友不增加真实出勤。
- 格子选中后，已在当天名单中的成员卡片暗淡、不再推荐高亮，悬停或聚焦显示“已在当天名单中”；仍可点击添加随行朋友。按成员身份匹配别名和大小写，今天第11人及之后也纳入判断；其他日期的计划不影响当天的已加入状态。尚未加入且有直接最佳拍档参加的卡片高亮；小局偏好、星期习惯、请假与连续打球风险使卡片暗淡，原因仅在悬停或聚焦时显示。暗淡不禁止选择，有风险时优先暗淡。

## 名单与日期

按北京时间切换日期。接龙输入实时保存原文和随行人员覆盖信息；今天计划反映前十人，修改计划时保留接龙第11人及之后的所有人。未来日期到来后自动载入对应名单。主动清空以空名单保存，刷新不会恢复已删人员。编辑历史订场时不写入当天计划，退出后恢复当天名单。

### 补记历史活动

整理图标先读取“活动时间／活动日期”，再移除说明并整理名单。例如“活动时间：11-09 (周一) 19:00 ~ 22:00”在2026年会选择2026-11-09；完整年份优先，省略年份时以北京时间当前年为准，临近跨年或星期不符需确认。编辑已有订场则以记录年份为参考。

接龙顶部显示可手动修改的活动日期。名单草稿、收款报表和订场保存共用该日期，但整理按钮本身不创建订场记录。已有订场改日期仍需确认后保存；目标日已有不同云端草稿需确认替换，其他日期不删除。

粘贴历史活动只在本机暂存，点击整理或手动确认后再按活动日上传，不覆盖今天的云端名单。无效或多日期须先确认使用当前日期，取消保留原文；没有日期则保留原日期。手动日期和从云端载入的已确认日期优先于未变更的活动说明，编辑成员不撤销确认；活动说明发生变化时重新确认。已选历史日期或待确认原文跨午夜不丢失，普通当天名单仍自动切换到次日。

## 同步与权限

Cloudflare 与 GitHub Pages 共用 D1 `session_plans` 表。GitHub 仅此计划 API 可写，成员数据库、账务、规则和历史订场仍只读。

- `GET /api/session-plans`：读取北京时间过去七天至未来六天的已保存行。
- `GET /api/session-plans?date=YYYY-MM-DD`：同时返回指定日期，支持补记七天窗口之外的历史草稿，无效日期返回400。
- `POST /api/session-plans`：保存任意有效活动日（不再限制七天窗口），字段为 `date / revision / mutationId / day`。`day` 含 `text / plusOverrides / slots`（固定十格）。允许两个正式站点及本地8787来源，沿用每分钟写入限流。
- 每天独立修订号，SQL条件写入保护跨设备并发；相同请求重试幂等。不同日期不会相互覆盖。
- 浏览器 `badminton.session-plans.v1` 保存云端快照和待同步草稿。输入先本地落盘，再防抖云端保存；断网、超时、丢响应和刷新保留待同步内容并重试。
- 修订冲突暂停同步，保留本机草稿，提供“保留本机修改”（需确认覆盖）或“采用云端名单”。不会自动静默覆盖其他设备。
- 页面显示保存状态。本机存储不可用时提示不要关闭页面；首次云端读取失败不会盲目覆盖未知版本。历史日期隐藏今天的概率按钮，但草稿下方仍提供“处理同步问题”入口；冲突状态标出具体日期。
- 异步日期读取采用最新请求优先；输入、当前订场上下文或选定日期变化后不再应用过时结果。

## 概率

计划是已确定参加的证据，六个确认名额满足原成局门槛，未结算时界面最多显示99%；不足六人仍使用原模型预测其余人员。已确认的人不再按取消概率折损，其他人员仍保留星期、朋友、人数偏好、请假与体力条件。未来计划只进入预测上下文，不伪造订场、出勤、学习标签或拍档关系。前几日计划可影响连续打球风险。

七天估计均在浏览器 Worker 中完成，保留最新请求队列，计算期间界面可继续操作。未来六天使用较小模拟预算；主日推荐沿用原预算。

## 文件与验证

- `session-planner-core.js`：北京时间、十格规范化、随行归属、近期真实出勤。
- `session-planner.js`：计划窗口、本地草稿、云端同步与日期切换。
- `chain-activity-date.js`：活动元数据日期识别、跨年和星期检查、手动确认依据。
- `src/session-plans.js`：来源验证、逐日条件写入及幂等重试。
- `migrations/0026_session_plans.sql`：新增计划表，不改动历史表。
- `scripts/verify-session-plans.js`：SQLite API契约、日期边界、重复朋友、清空、冲突、概率与学习隔离。
- `scripts/verify-session-planner-ui.js`：真实计划控制器回归测试，覆盖已加入成员的高亮排除、别名与大小写、跨日期隔离、完整名单、朋友归属、Backspace 清空、自定义输入及提示移除。

日期功能使用原有0026表，不需要新增迁移。`npm run test:chain-date` 覆盖识别与真实UI/控制器联动、历史读写、取消确认、手动覆盖、刷新、跨午夜、断网冲突和异步切换；`scripts/verify-deployed-chain-date.js` 只读核对生产资源及历史日期API。

首次发布先执行 `npm run d1:migrate:remote`，再构建部署 Worker，最后推送 GitHub。`npm test` 已包含 `npm run test:session-plans`。
