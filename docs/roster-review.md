# 收款前人员核对

## 解析与等级

- 完整数据库名字/外号优先匹配，大小写和兼容全角字符归一化；不把 `oi` 从未登记的 `choi` 中猜出。
- 登记成员后跟纯数字表示独立的一位随行人员：`oi1` → `oi+1`，`oi+2` 是第二位随行人员，不表示增加两个人。数据库确实登记了完整 `Hx7`、`1fan`、`oi1` 等名字时，完整名字优先。
- 支持 `【3】名字`、`【3级】名字`、`【2.8级】名字`。
- 以小数文本计算边界，避免二进制浮点误差：小数部分 `<0.3` → 当前整数，`0.3≤小数部分<0.8` → 当前整数+0.5，`≥0.8` → 下一整数。
- 例如 2.2→2、2.3→2.5、2.7→2.5、2.8→3、3.2→3。多位小数也使用同一边界，而不是默认的“最近半级”四舍五入。
- 标准等级为 0.5～9 的全部半级；无法转换到此范围的输入在核对窗口中手动处理。现有自定义等级分组保持原范围，未覆盖的新增半级显示为“未分组”。
- 数字等级作用于本次参加者，包括随行人员，不借用带来者等级。小程序名单的 🌸 性别标记仍沿用原规则。

## 唯一核对窗口

点击“群收款”后先收集全部未处理问题，没有问题才直接进入收款。

- 登记成员等级与输入标准等级不同：选本次等级，明确回答是否更新数据库。
- 登记成员缺少等级：选等级并明确选择更新或保持不详；没有猜测等级。
- 陌生名字：如果是已有成员，可选择“已有成员，仅本次关联（不保存外号）”，或将该名字添加为新外号；如果确实是新成员，创建“球友”/“特殊”档案；如果是已有成员的随行人员，可绑定带来者而不创建档案。
- 仅本次关联：收款、出勤归实际参加者，收款名单及已解析名单使用数据库中的首个名字；原始报名原文保留。身份决定随本次名单保存，同一名单重新打开或刷新不重复询问；新活动仍需重新确认该陌生名字，不污染永久外号索引。等级差异继续在同一行明确选择是否更新，身份关联本身不更新档案。
- `成员+编号`：确认实际已有成员（代报名）、未登记随行人员，或登记为新成员。
- 新成员首次参加并带人：将本人选为“新成员，加入数据库”后，其档案草稿立即加入带来者下拉框，标为“本次待新增”并显示原报名行号；无需先入库或重复打开窗口。草稿使用稳定键关联，改名、等级或分组时显示同步更新，已选归属不丢失。
- “随行人员（不入库）”可关联已有成员或本次待新增成员。完整数据库名字优先；未匹配到已有成员的“刘1 / 刘+1”唯一对应待新增“刘”时自动预选并展示说明，仍可更改。多个同名草稿不自动猜；新增更完整的数字名字时重新计算未手动确认的建议；手动选择不会被自动覆盖。
- 支持多位新人各自带多位随行人员、随行人员写在本人前面。随行人员的性别和等级单独核对，不继承带来者；编号 +2 仍表示单独的一位随行人员。本人记出勤与带人次数，随行费用归带来者；随行人员本身不创建成员档案。
- 全部资料先校验再统一新增，以保存回执中的草稿键 → 成员 ID 映射绑定本人和随行人员，不依赖报名、插入或入群序号顺序。取消不入库；缺失 ID 回执、无效资料、取消新增的带来者或只读版均不能进入收款；失败保留选择，丢失响应后重试同一请求不重复创建新人。
- 选择已有成员后，身份和其等级问题在同一行继续核对，不增加二次弹窗。
- 代报名确认到已有成员后，`playerId` 和 `ownerPlayerId` 都指向实际参加者，`isCompanion=false`。收款与本人出勤归实际参加者，不累计报名者带人次数。
- 未登记随行人员保留 `playerId=null`、带来者 `ownerPlayerId` 和 `isCompanion=true`，独立性别/等级快照，费用及带人次数归带来者。
- 防止将代报名映射到名单中已经直接报名的同一成员，避免重复收款。
- 选择“不更新”不改成员数据库，本次排序、预估和保存快照仍使用所选等级。

待新增带来者仅在当前核对窗口中用 `new:草稿键` 引用；确认后持久化的核对决定只使用真实 `ownerPlayerId`，可附带标准随行显示名 `companionName`，报名原文仍保留。无需新增数据库表或迁移。

核对决定保存在当日名单的 `plusOverrides.reviewResolution` 中，以原始报名内容及出现次数为键。原文不改写；同一名单及档案等级未变时不重复问。修改原始报名或后续修改数据库等级会重新核对；历史编辑的 `preserveSnapshot` 不进入当前成员档案更新。

新建成员可填写可选的多行备注。桌面端备注位于数据库等级右侧，手机端排列在等级下方；每位新人的备注独立保存在核对草稿中，切换处理方式、等级或保存失败后均保留。确认时备注随成员资料在同一事务写入 `players.notes`，首尾空白会去除，未填写按空备注保存；已有成员的等级/外号更新不修改其备注。沿用既有备注字段，无需迁移。

## 提交与安全

仅本次关联且不更新数据库等级时，不调用成员档案写入接口、不创建成员或保存外号，只保存当日名单的身份决定。只有明确选择更新等级时才提交等级修改，仍不会把本次玩笑名字加入外号。

`POST /api/roster-review` 只允许管理版：批量校验名字/外号冲突、等级和成员分组，并同时提交所有等级更新、外号及成员创建；球友成员的入群序号在同一事务内追加。

`0028_roster_review_commits.sql` 保存幂等请求编号、内容摘要和新成员ID。事务内的 CHECK 校验检测读取与提交之间的成员档案变化；任一语句失败全部回滚。丢失响应后重试相同请求不会重复创建成员。保存错误保留填写内容，不进入正式收款窗口；保存期间阻止关闭窗口与重复提交。取消不写入数据库。

核对窗口高于侧栏，并把侧栏、背景主界面及底层接龙窗口设为不可交互；沿用键盘焦点陷阱与关闭后焦点恢复。窄屏为单列字段、独立滚动内容和固定可见的操作栏。

GitHub 备用版继续保持成员数据库只读：可仅本次关联已有成员、确认代报名或未登记随行人员、选择本次等级；新增成员、外号或更新数据库等级需打开 Cloudflare 管理版。

## 验证

- `npm run test:roster-review`：执行实际生产解析/规划函数与 SQLite 上的 D1 事务接口测试，包括等级边界、数字名字、陌生人登记、仅本次关联（实际确认不写档案、标准名字收款、原文保留、同名单免重复与新活动重新核对、只读版、独立等级选择）、代报名归属、重复保护、历史快照、回滚、并发修改、外号冲突及幂等重试。
- `scripts/verify-roster-review-pending.js`（包含在 `npm run test:roster-review`）：首来新人带人、自动建议及手动优先、完整数字名字、多新人/倒序/多随行、改名后绑定、独立性别等级、取消草稿、缺失回执、收款/出勤归属、只读校验与幂等重试。
- `npm run test:special-roster`：33 人小程序名单原文、等级、性别、随行编号及排序。
- `npm test`：现有全套收款、日历、出勤、成员统计、摇人、数据库及预估回归。
- 真实浏览器在隔离本地 D1 上验证：必填校验、取消不写入、失败保留选择、批量新增/改级/加外号、实际收款/出勤归属、重复打开免询问，以及桌面/手机的核对窗口。
