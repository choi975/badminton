# 摇人即时交互与后台保存（2026-10-27）

## 排查基线

本地128名成员、55条订场记录快照，单次同步概率计算约1.8–2秒。原“今天不打球”和规则删除在等待HTTP后先计算不带候选的成局概率，再计算带候选的预测，CPU合计约3.8秒，均在主线程执行。多人规则还逐条等待HTTP。拍档操作等服务端确认后才更新，筛选/加入接龙也可能触发完整重算。

## 实现

- forecast-worker.js 在专用浏览器Worker中运行原概率引擎，算法和样本口径不变。每次同时返回候选及今天/明天概率，跳过未展示的反事实贡献。
- forecast-client.js 只允许一个计算进行、一个可替换的最新请求等待，合并重复请求。过期结果不更新界面，失败不回退到会卡住界面的同步计算。
- 页面保留上次概率并标示“更新中”；没有结果显示“暂无估算”。筛选、局部行移除、排序和规则状态立即生效。成员统计使用已加载结果和轻量覆盖层，不在渲染过程中反复全量统计。
- optimistic-sync.js 将每项规则/拍档意图先保存到独立localStorage键，再更新界面。刷新时重建乐观视图；云端已确认状态与未同步意图分层，旧响应不能抹掉仍待保存的修改。
- 同一浏览器多页通过 Web Locks 串行派发；不支持时仍由服务端幂等回执避免重复执行。网络错误、408/429/5xx使用递增等待，最长30秒；恢复网络时继续。保存成功安静清除待同步状态，明确4xx拒绝只移除对应意图并提示原因。服务器冲突返回最新状态，撤回冲突的那次操作，不盲目重放相对排名。
- 本机存储失败时不展示虚假的“已应用”。界面显示待同步数量；完全关闭浏览器后，队列会在下次打开管理版并联网时继续，不承诺浏览器关闭后仍有后台进程。
- 成员性别/等级等已有即时编辑增加按成员串行保存，失败仅撤回本项，后续字段保持；这些旧接口失败仍明确报错，不冒充已持久化。
- 订场落账、余额、删除历史记录等保留服务端确认，避免钱款/历史记录在写入失败时显示成功。它们不再被概率主线程计算阻塞。

## API与存储

0025_shake_mutation_receipts.sql 只新增回执表和 app_settings.shake_revision，不删除或迁移业务记录。

- GET /api/shake-state：同一个D1只读批次返回规则、拍档覆盖和单调递增修订号。
- POST /api/shake-mutations：仅管理版接受，每项有UUID、kind及payload。
- 规则变更与回执、修订号在同一原子批次提交；重复UUID只能复用完全相同的请求。重试读取当前确认状态，而不是把历史响应重新覆盖到客户端。
- 拍档相对移动使用版本compare-and-swap，与回执一起提交；即使服务器成功但响应丢失，重试也不会再上/下移一次。
- 尚未确认的规则/拍档不进入训练快照；后台模型完成且保存确认后才继续保存匹配的真实接龙状态。试算、只读保护不变。
- 快照记录shakeRevision和规则/拍档；管理版使用独立确认缓存恢复最近状态，GitHub端只读且不会创建写队列。

## 验证

scripts/verify-instant-interactions.js 覆盖SQLite事务回滚、并发回执、丢响应重试、临时规则删除、持久化恢复、单项拒绝、存储不可用、过期Worker结果及成员字段并发。

本地浏览器注入每次2秒网络延迟，连续三次“今天不打球”在约39/38/32ms内完成界面更新，后台顺序保存。另覆盖失败撤回、响应丢失后仅保存一次、刷新恢复未同步规则、连续拍档下移及手机触屏操作。性能数值为本机验收，不是所有设备的保证。
